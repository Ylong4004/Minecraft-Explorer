# Minecraft Explorer

Windows 原生 Minecraft Java 存档与内容管理器，Rust + Slint + SQLite。当前版本 **1.0.0**，支持中英双语、深浅主题、内容索引、备份和空间分析。PCL2、HMCL、PCL CE 支持打开启动器；可另外绑定某个版本的 BAT / CMD 启动脚本。[English documentation](docs/README.en.md)

[Fimel 作品与下载](https://studiofimel.com/#/works/minecraft-explorer) · [GitHub 源码与问题反馈](https://github.com/Ylong4004/Minecraft-Explorer)

## 第一次使用

1. 从 Fimel 作品页下载 `MinecraftExplorer-1.0-win-x64.exe`，直接双击运行，无需解压或安装。程序可放在任意有读取权限的目录，不必放进 Minecraft 目录；更新前先退出旧版。缓存默认写到 `%LOCALAPPDATA%\MinecraftExplorer\`，不在游戏目录创建扫描文件。文档 ZIP 发行包仍可使用其中的 `MinecraftExplorer.exe`。
2. 点击 **设置 → 添加 Minecraft 根目录**。PCL 的示例是 `D:\PCL2\MinecraftPcl`，即 `versions` 的父目录。独立整合包可用“添加自定义游戏目录”，同时指定关联根目录；可重复添加多个来源。
3. 添加后自动切换到 **空间分析**，选中新目录，先刷新索引，再紧接着分析这个目录。等待期间显示“索引刷新后自动分析新增目录”，无需再点“重新分析”。条目先出现，名称、图标和大小随后补齐；**待统计**表示尚未完成的大小，**≥**表示因权限或跳过链接而只得到下限。取消保留目录关联和已有结果，并跳过后续自动分析；按 **F5** 重试索引，或在空间分析点击“重新分析”。关闭程序也会停止待执行的分析。
4. 点击 **全部存档**，在顶部输入地图名、实例名或路径。用“全部游戏目录”筛选某个整合包，再按大小或游玩时间排序。单击一行查看右侧详情，用“打开位置”或 **Enter** 在资源管理器中定位；这不会打开 Minecraft 世界。
5. 在详情收藏条目，或填写逗号分隔的标签后保存。以后可从 **收藏**、**最近打开**找回，并组合使用根目录和完整标签筛选。

## 找到所属版本并启动

先在 **设置 → 添加启动器**选择 PCL2、PCL CE 或 HMCL，填写启动器文件、工作目录和它使用的 Minecraft 根目录。PCL2 / PCL CE 选择 EXE；HMCL 选 JAR 时还需指定运行 HMCL 的 Java。

选中存档、模组或其他条目，点击详情中的 **设置关联**，核对启动器、目标版本和实际游戏目录后保存。独立实例不能关联到另一个实际目录；共享存档需要自己选定目标版本，世界历史版本号不会自动成为启动目标。

- **打开所选启动器**：打开原程序，然后在启动器里手动选择详情提示的版本，由它正常登录和管理运行参数。
- **启动关联脚本**：为这个版本准备启动器生成的 BAT / CMD，在“设置关联”中选择脚本和工作目录，保存后点击此按钮。没有脚本时按钮不可用。

如果启动器提供生成/导出启动脚本功能，请选择目标版本导出。PCL 的 `LatestLaunch.bat` 记录上一次游戏启动：先确认上次启动的是目标版本，再另存为该版本专用文件；不要直接绑定会被其他版本覆盖的 `LatestLaunch.bat`。复制脚本后，如包含相对路径，应将工作目录设为原启动器所用的目录；不填时默认使用脚本所在目录。

本程序通过 Windows 执行用户指定的文件，不解析脚本、不读取或刷新其中的登录信息。脚本可能含有敏感登录参数，请自行保管，不要分享；登录失效、Java 或路径变化时，回到原启动器重新生成并绑定。脚本退出成功不证明游戏已经启动，请查看游戏窗口或脚本日志。清空脚本路径再保存可取消绑定；更换目标版本会清空脚本字段，需要重新选择。

脚本入口与启动器原生指定版本接口是不同能力。当前仍没有经过真实验证的 PCL2 / PCL CE / HMCL 指定实例外部 CLI，详见 [接口核查与脚本说明](docs/LAUNCHER_RESEARCH.md)。实际 Minecraft 启动仍需用用户自己的版本脚本验收。

## 运行

双击单文件 EXE，或打开文档包中的 `MinecraftExplorer.exe`。面向 Windows 10/11 x64；SQLite、Slint 软件渲染器、应用图标和许可原文编入程序，无需安装 Rust 或 Java 来运行本程序，不需要旁边放置 DLL、图片或许可文件。依赖 Windows 系统组件及 **Microsoft Visual C++ x64 运行库（VCRUNTIME140.dll）**；若提示缺少此 DLL，请安装 [Microsoft 官方 VC++ Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)。尚未在干净的 Windows 10/11 虚拟机验收，不承诺完全零系统依赖。HMCL JAR 自身需要匹配的 Java。

1. 设置 → 添加 Minecraft 根目录。你提供的测试位置应选择 **`D:\PCL2\MinecraftPcl`**，即 `versions` 的父目录。
2. 也可添加多个根目录，或添加自定义游戏目录，并明确指定其归属根目录。
3. 在全部存档、资源包、模组、光影包、数据包页面搜索名称、文件夹名、实例 ID、完整路径及文件内声明的元信息；支持名称、大小、游玩/修改时间、最近打开和所属目录排序，并按实际游戏目录筛选。数据包必须在目录或 ZIP 根部同时具有文件 `pack.mcmeta` 和目录 `data/`；ZIP 的 `data/...` 子项也可证明该目录存在。`.git`、`tools` 等普通目录和只有元信息的 ZIP 不再计为数据包。
4. 选中条目查看真实路径、元信息来源、空间占用和版本归属。列表及详情按需加载世界 `icon.png`、包 `pack.png` 或模组声明的 PNG 图标；缺失或损坏时显示占位图。可复制路径或在资源管理器中定位。F5 完整刷新；Ctrl+F / Ctrl+K 聚焦搜索；Esc 关闭弹层。
5. 详情中可收藏、保存逗号分隔的标签，并在收藏、最近打开页面查看。标签筛选匹配完整标签。查看详情、成功发送定位请求、成功创建所选启动器进程会记录最近打开；这些记录只写本程序数据库。
6. 目录监控默认开启，可在设置关闭。变化合并后重新发现条目，刷新受影响内容的元信息和大小，并在同一个后台任务内补齐受影响游戏目录的总大小。其他实例不重新遍历。版本 JSON、官方实例配置变化或事件丢失会触发完整刷新。
7. 重复检测由用户主动开始，先按文件大小筛选，再读取整个文件计算 BLAKE3；只列出资源包、模组、光影包、数据包文件的重复候选，支持取消。文件夹和世界不参与重复哈希，不自动清理；手动回收仍需逐次预览并确认。
8. 设置中添加 PCL2、HMCL 或 PCL CE 安装，指定程序文件、工作目录和 Minecraft 根目录。PCL CE 独立保存安装与关联；PCL2/PCL CE 使用 EXE，HMCL 可使用 EXE 或 JAR，JAR 另需选择运行 HMCL 的 `java.exe` / `javaw.exe`。世界/版本详情中的“设置关联”可保存具体版本 ID、实际目录和此实例的默认启动器，同实例的其他内容继承该选择。

“打开所选启动器”使用指定安装启动原启动器，由它处理账号和运行设置。原启动器外部接口仍为 `OpenOnly`，绑定脚本后另用“启动关联脚本”；**打开启动器不表示选中版本或启动游戏**。共享世界需手动关联。失败时可切换到关联同一根目录的其他安装，程序不会自动打开另一安装。详见 [接口核查](docs/LAUNCHER_RESEARCH.md)。

## 文件操作与备份

在列表左侧勾选条目，或先选中一项查看详情，再选择重命名、复制、移动、备份或移入回收站。全选最多 256 项；整个操作最多 100000 个文件/目录、8 MiB 清单，超过限制时请分批。重命名一次处理一项，并保留文件扩展名。先生成预览，核对真实源/目标路径、文件数量与逻辑大小，再勾选确认并执行；修改参数后必须重新生成预览。确认后的源内容变化会中止操作。

复制/移动的目标父目录必须属于已经添加的游戏目录，且对应所选类别：存档选择 `saves`，模组选择 `mods`，资源包选择 `resourcepacks`，光影选择 `shaderpacks`，数据包选择目标存档的 `datapacks`。目标目录需要事先存在。重名默认停止，可选择自动加序号保留两份；不提供覆盖。复制在目标旁创建临时副本，逐文件核对完整 BLAKE3 后提交；跨磁盘移动使用同样流程，最后把原件移入 Windows 回收站。回收失败或提交后取消时保留源与目标两份，并记录需要检查的路径。

备份父目录必须位于已添加游戏目录之外。备份采用目录副本，包含 `content/<原名称>` 和 `minecraft-explorer-backup.json` 校验清单；不会复制运行锁 `session.lock`。在「清理与备份」选择该备份目录和目标内容父目录，可校验后恢复；损坏的备份不会恢复。回收的原件通过 Windows 回收站还原。

版本定义仅开放明确范围的回收操作：默认只处理该版本目录内匹配目录名的版本 JSON 及同名 JAR，或已唯一识别的其他版本 JSON 及配套 JAR，保留其他配置、归档和存档；无法确认核心文件时中止。只有确认存在独立游戏目录时，才能另选整个独立实例目录。共享/自定义游戏目录、Minecraft 根目录、`versions`、内容容器、用户主目录、程序数据和启动器文件受到保护。回收站只开放本机固定磁盘，使用 [Windows IFileOperation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags) 回收标记，并在回调中拒绝永久删除请求；不可用时中止。

运行中的存档通过 Windows 文件共享和 `session.lock` 锁检查拒绝操作。仍应先退出 Minecraft 和同步/备份工具，避免外部程序在任务中途修改文件；本程序不能提供 Minecraft 热备份。批量操作逐项提交，取消后已完成项保留；当前 Windows Shell 单项回收完成后才处理取消。任务中关闭窗口会请求取消，等待收尾后退出。正常失败会清理未提交的临时副本，异常退出则保留供检查，不在重启时自动删除。操作记录默认保存在 `%LOCALAPPDATA%\MinecraftExplorer\operations\`，「清理与备份」显示未完成任务的源、目标及残留临时副本。重命名/成功移动后同步收藏、标签和最近记录，并刷新受影响索引；受影响实例总大小会自动重算，F5 可主动完整刷新。

## 数据与操作边界

配置与缓存默认位于 `%LOCALAPPDATA%\MinecraftExplorer\index.db`；`MINECRAFT_EXPLORER_DATA` 可指定独立缓存目录，请与游戏原文件分开放置。索引格式从阶段 1 的 v1 事务迁移至 v2，保留原配置与条目；高于 v2 的未知格式会拒绝打开。收藏、标签与最近打开记录独立保存，扫描不会覆盖它们，路径暂时消失或移除后重新添加同一路径仍可恢复注释。“移除目录”仅移除本程序关联与索引。

世界名/游玩时间优先来自 gzip 或未压缩的 `level.dat`，必要时只读尝试 `level.dat_old`；缺失/损坏时明确标注目录名和文件时间为替代信息。世界历史版本不是启动目标。跳过符号链接/junction/重解析点；缺权限时大小显示下限。逻辑大小不是磁盘实际分配空间；世界已包含在其游戏目录大小内，不能重复相加。离线目录保留缓存。

资源包/数据包读取 `pack.mcmeta`；模组读取 Fabric、Forge、NeoForge 和旧 `mcmod.info` 声明。显示名、描述、ID、版本、作者及兼容范围来自这些文件，不根据文件名猜测，也不把声明范围当作兼容性检查。光影包缺少统一元信息时保留文件名、路径和明确提示。ZIP/JAR 仅读取指定元信息与小图标，限制读取、解压和中央目录大小，不解压到游戏目录。损坏资源包、模组和光影包仍保留可查路径；数据包无法验证规定结构时不加入列表并记录诊断，暂时无权限时保留旧缓存。结构失效后，完整或相关增量刷新会移除旧误识别条目。

本程序的扫描、图标预览、空间分析和重复检测不修改游戏内容，不上传文件清单或存档数据；文件操作由用户预览确认后执行。打开原启动器后，它会执行自身正常行为。暂时请对同一缓存运行一个程序窗口。目录备份会占用额外磁盘空间，移动也需要先容纳完整目标副本。

## 空间分析与界面

空间分析 → 选择全部来源、根目录或实际实例目录 → 重新分析。若另有任务，先完成或取消后再分析。后台用最多 4 个线程统计互不重叠的子目录，上方显示已读取文件数和耗时；共享目录与重叠来源只计一次。矩形面积对应大小，双击目录钻取、上一级返回、悬停查看完整路径及归属、右键定位；已索引的内容可联动到列表。六类占用图展示存档、资源包、模组、光影包、数据包和其他文件。建议只辅助核对，不自动删除。

树图一次最多绘制 256 个矩形，小项合并；最多保留 100000 个绘图节点，省略节点的字节仍包含在父目录总量中。遍历采用流式枚举，目录深度上限 1024 层；不可读、链接或超出深度的内容显示大小下限。分析为内存快照，鼠标移动不重新扫描，文件变化后用“重新分析”更新。原内容列表继续使用虚拟化和有界图标缓存。

本程序使用普通权限目录枚举，没有直接读取 NTFS MFT，也不保证与 WinDirStat 的管理员加速扫描相同速度。[WinDirStat 官方说明](https://github.com/windirstat/windirstat/wiki/Advanced-Topics) 中的 MFT 加速面向本机 NTFS 整盘，普通文件夹扫描不使用该方式。文件数量、磁盘和安全软件都会影响首次分析耗时。

设置中用“界面语言”和“界面主题”下拉框切换中文 / English、深色 / 浅色，立即生效并自动保存，旧配置默认中文深色。0.4.2 修复了实际下拉框选择无效的问题，并避免快速切换时旧保存回执覆盖新选择。文件名、路径和第三方原始声明保持原样。右键菜单提供定位、复制路径、重命名、复制、移动、备份、回收、收藏和打开启动器；F2 重命名、Delete 回收、Enter 定位、上下键选择、Ctrl+A 全选、Ctrl+Shift+A 清空、Ctrl+C 复制路径、Ctrl+B 备份、Ctrl+F/K 搜索、F5 刷新、Esc 关闭弹窗。输入框保留自身编辑快捷键，文件操作快捷键只打开确认预览。

原创“草地方块＋放大镜”图标已嵌入 EXE 与窗口。矢量源在 `assets/icon.svg`，七种尺寸的 Windows 图标在 `assets/icon.ico`，窗口图标为 `assets/icon-256.png`；均使用本项目 MIT 许可。需要调整图形时修改 `scripts/generate_icon.py`，安装 Pillow 后运行该脚本重新生成。正常构建直接使用仓库中的成品，不需要 Python 或 Pillow。

Windows 为启动器 EXE 配置“以管理员身份运行”时，程序会显示系统 UAC 授权，取消授权会明确报告。

## 构建

稳定 Rust（`rust-version = 1.92`）、Visual Studio C++ Build Tools 和 Windows SDK。当前验证为 Rust 1.99.0、MSVC 14.44、Windows SDK 10.0.26100.0。Slint 固定 1.18.1，采用 winit + software，未引入 Electron/WebView。

```powershell
cargo fmt --check
cargo check --all-targets --all-features
cargo test --all-targets --all-features
cargo clippy --all-targets --all-features -- -D warnings
cargo build --release
```

本工作区还提供隔离工具链包装脚本（不修改全局 PATH）：

```powershell
.\scripts\cargo.ps1 build --release
.\scripts\cargo.ps1 -CargoArgs @('test','--all-targets','--all-features','--','--nocapture')
```

输出 `target/release/minecraft-explorer.exe`。发布时复制到 `dist/MinecraftExplorer/MinecraftExplorer.exe`，并附文档、第三方许可文本；`scripts/package.ps1` 执行打包与 SHA256 生成。

项目空间清理：`target/` 是可重建的编译产物，`.test-artifacts/` 是测试目录、截图和指标，均可在关闭构建/测试任务后清理；删除它们不影响已打包的 `dist/`。`.tools/` 包含本项目正在使用的 Rust 工具链与依赖缓存，继续开发时建议保留；删除后需要重新配置或下载。源码、`Cargo.lock`、`licenses/` 和 `.git/` 应保留。

只读命令行扫描（缓存必须放到游戏根目录之外）：

```powershell
.\scripts\cargo.ps1 -CargoArgs @('run','--release','--bin','inspect','--','D:\PCL2\MinecraftPcl\versions','.test-artifacts\real-pcl2')
```

该工具接受根目录或 `versions` 并使用同一扫描器，输出 `report.json` 和独立索引。桌面添加目录时直接选择根目录。

项目新编写源码为 MIT；Slint 采用 Royalty-free 2.0，设置 → 关于包含实际 `AboutSlint` 控件，发行包保留许可与归属。详见 [许可说明](docs/THIRD_PARTY.md)、[架构](docs/ARCHITECTURE.md)、[测试](docs/TESTING.md)、[阶段记录](docs/DEVELOPMENT.md)。

单文件 EXE 内置项目 MIT 及依赖许可原文。在 **设置 → 关于 → 导出第三方许可** 中，程序在自己的数据目录创建 `MinecraftExplorer-1.0.0-licenses.txt` 并定位该文件；双击即可查看。仅在主动导出时创建，不写入游戏目录，也不覆盖已有不同内容的文件。依赖变化后，重新运行许可收集及 `scripts/embed_licenses.py <收集目录>`，更新内置资源后再构建发行版。
