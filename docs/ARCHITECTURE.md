# 架构

## 0.4.2 设置与自动分析状态

Slint ComboBox 的 selected 参数是显示文字，外观选择通过控件的 current-index 判断。UI 即刻更新本地外观状态、动态详情和分析图，后台保存使用请求代次；普通设置事件在外观请求待保存期间保留最近选择，保存回执只确认最新请求。

新增目录保存后排入优先的 ScanAdded 任务，UI 选择该目录并显示等待索引的状态。索引正常结束后继续分析新增目录，整个过程共用原后台任务门闩和取消信号；取消或关闭不会重新启动后续分析。程序赋值范围的延迟回调与用户手动切换区分处理。索引发现实例会更新范围模型，但以去重且排除已包含子目录后的物理路径集合比较；同一范围不会清空新快照。

主 EXE 使用 embed-resource 编译 assets/app.rc，图标包含 16 / 24 / 32 / 48 / 64 / 128 / 256 像素，版本来自 Cargo 包元数据。Slint Window 使用编入二进制的 icon-256.png；生成器与 SVG 留在源码中，发布程序无需外部图标。

## 阶段 4 的空间快照与界面状态

空间分析独立线程使用现有任务互斥与取消信号，只读取路径与文件元信息，不读取登录文件内容。全部来源包含显式根/自定义目录及发现的游戏目录，经规范路径与父子范围去重后遍历；共享文件目录只进总量一次。大小为逻辑字节，不按硬链接对象或磁盘分配簇计费。离线或不可读来源不会阻止其他来源，跳过的内容使结果成为下限。

保留绘图节点限 100000 项；不再保留的文件字节聚合到最近保留的父节点，流式遍历仍继续统计。目录深度上限 1024，超过时跳过并标明下限。布局按大小二分，最多 255 个独立条目加一个合并条目，阈值为当前层总量的 0.05%。绘制坐标归一化，随画布尺寸缩放，悬停只更新文字，钻取只访问已读内存树。切换范围使旧结果失效，明确点击重新分析才读取新文件。

Settings 的 english / light_theme 使用 serde 默认值兼容旧配置，仍写 SQLite v2 设置 JSON。自绘颜色和 Slint Palette 同时响应主题；动态文件名和第三方声明保持原文。翻译按完整消息或完整格式模板匹配，仅已知错误/归属字段递归翻译；不会进行任意中文片段替换。模板由索引后台线程预热。原 ListView 和可见行图标缓存继续保留，键盘选择联动滚动位置。

启动器进程保留 Direct / Shell 两种句柄，仅 Windows 错误 740 且无参数 EXE 时调用 ShellExecuteExW。系统处理原安装的管理员要求；取消 UAC 返回可显示的错误。OwnedHandle 负责释放系统句柄，查询退出状态仍不推断游戏运行。

## 目录与归属

Root、Version、Instance、World 与 ResourcePack、Mod、ShaderPack、DataPack 分开建模；ID 使用类型 + 规范化真实路径，Windows 大小写与长路径前缀统一。同名世界保留不同 ID。共享 `saves` 只发现一次。版本目录中实际存在 saves/mods/resourcepacks/shaderpacks/screenshots 时标记独立内容目录；这不是对启动器隔离设置的推断。无唯一 JSON 或缺少 ID 则标为未知。基础版本与 Loader 只由 JSON 字段、明确库坐标识别。

每个实际游戏目录枚举 `resourcepacks`、`mods`、`shaderpacks` 的直接子项；资源包/光影包支持 ZIP 与目录，模组支持 JAR、`.jar.disabled` 与目录。每个世界单独枚举其 `datapacks`，并记录所在世界和实际游戏目录。多个来源指向同一物理游戏目录时先去重，避免共享内容重复计数。

数据包另需根级 pack.mcmeta 普通文件及 data 目录；ZIP 可通过 data/... 条目确认隐式目录，不搜索包装子目录。结构缺失返回非数据包，可读但结构损坏的归档不计入；无权限候选使来源标记未完成以保护旧缓存。增量清理允许移除物理路径仍存在但已确认失去数据包结构的旧条目。旁置文件操作临时目录使用 .minecraft-explorer- 前缀，内容发现跳过。

官方 `launcher_profiles.json` 仅投影 profiles 的 name/gameDir，不反序列化账户信息。没有解析 PCL/HMCL 私有账户配置。自定义游戏目录的归属由用户选择根目录确认。

NBT 读取及解压均限制 16 MiB；版本 JSON 限制 4 MiB。读取失败保留条目。每次遍历前检查路径各组件，默认不跟随 reparse point；写操作另由 operations 的来源/目标策略、完整快照、运行锁检查和不覆盖提交保护。

内容解析仅读取已识别的 `pack.mcmeta`、`fabric.mod.json`、Forge/NeoForge TOML、旧 `mcmod.info` 等条目。单个元信息条目上限 1 MiB、一次元信息预算 4 MiB；ZIP 中央目录上限 8 MiB、条目数上限 40,000，多模组声明最多展示 256 条。压缩与解压后的长度均检查，重复归档路径、路径穿越、链接、加密及不支持归档会明确失败，不向游戏目录解压。包描述支持有界文本组件；模组构建占位符保留原声明并提示，兼容范围按原声明展示，不执行兼容性求解。

图标来自世界 `icon.png`、包 `pack.png` 或模组声明的 PNG；读取上限 2 MiB、解码最大 1024×1024、分配上限 8 MiB，缩为最大 96×96。缺失、超限或损坏图标使用占位图，不阻止列表显示。

## 大小口径

World 包含世界完整目录；Version 仅统计顶层 JSON/JAR 核心文件；根 Instance 排除顶层 `versions`；独立/自定义 Instance 排除顶层 JSON/JAR。内容文件按文件长度、目录包按递归文件长度统计。各行大小解释其类型：世界已包含数据包，游戏目录已包含世界及内容，不能相加做总占用。未知扩展核心文件暂未分类。文件不可访问或跳过链接时为可统计的下限；压缩文件、稀疏文件按逻辑长度计算。

## 后台与索引

UI 只接收后台结果。命令线程查询 SQLite 并处理设置、详情及系统操作；扫描另用线程和 SQLite 连接，串行遍历（并发度 1），先发布发现结果，再优先读取世界，最后实例大小。每个文件/目录检查取消；进度节流 200ms，UI 每 60ms 处理消息，搜索防抖 180ms。查询请求带代次，忽略过时结果。虚拟列表使用 Slint ListView，不创建全量绘图控件。

列表行图标由可见 ListView 行请求，单独的后台图标线程按已显示条目的路径快照读取/解码，避免阻塞搜索与设置命令，也不依赖扫描期间的数据库写锁。请求通道容量 64，UI 最多缓存 256 个图像结果，缺失结果也缓存；满队列时延后有限数量请求。缓存键含条目 ID、修改时间、大小、预览修改时间与声明的图标路径，只有当前键一致的结果才更新行与所选详情；内容刷新会使旧键失效，扫描开始清除缺图缓存以允许重试。后台传递 RGBA 字节，Slint 图像及行模型仅在 UI 线程更新。

SQLite WAL / NORMAL，busy_timeout 5 秒。`settings` 单行 JSON 保存 sources/launchers/mappings/default_launcher/instance_defaults/watch_enabled。`items` 包含 id、kind、source、game_dir、name、search、size、time_ms、ownership、available、generation、json。类型+大小/时间、game_dir、source 建索引；模糊子串查询仍需扫描匹配范围，尚未验证百万条数据。

当前 schema version 2；事务迁移保留 v1 的配置与索引，新增字段由 serde 默认值读取，高于已知格式的数据库直接拒绝打开。`annotations` 单独保存 favorite、tags_json、search、last_opened_ms；`annotation_tags` 保存完整标签及规范化键，索引 tag_key/item_id。扫描 upsert 只更新 `items`，query/get 合并用户注释。删除失效条目或移除来源不删除注释，同 ID 恢复后重新合并。标签筛选用完整键匹配，模糊搜索包含标签和可信内容描述/ID/版本，并转义用户输入的 LIKE 通配符。查看详情、定位请求成功、成功创建启动器进程在本数据库记录最近打开，不通过修改游戏文件时间保存记录。

发现时事务写入新条目并标记代次，已有元信息继续可见；扫描完写入实际结果。完整成功的来源才清理旧代次；取消保留旧索引。离线来源标记不可用并保留缓存；局部读取失败不把整个来源标为离线。

## 文件变化与重复候选

notify 监听配置根目录、自定义目录和发现的外部 gameDir，去除已有递归根覆盖的路径。默认不跟随链接，并对事件路径的最近存在父级再做重解析点检查。事件队列有界，900ms 安静期合并，持续写入最长 3 秒发送一次批次；溢出、native 错误及订阅重建标为需要完整发现。失效根低频重试；Windows 卷号/文件 ID 与 Unix dev/inode 检查根目录是否被删除重建，避免订阅停留在旧目录对象。

普通变化先重新发现成员，读取新增或受影响叶条目的元信息和大小，并在同一后台任务内重算受影响 Instance 的总大小。版本 JSON、`launcher_profiles.json` 或事件丢失使用完整扫描。仅当来源发现完整且路径明确已不存在、或已确认丧失数据包规定结构时移除缓存条目；取消不进行清理。监控可关闭，手动刷新仍可使用。

### 0.4.1 扫描优化

`SizeCache` 保存一次任务内已完成子树的逻辑字节和完整性，实例、世界、目录包及外层目录复用它；不跨扫描周期复用未经验证的大小。元信息阶段保留缓存大小；未知值显示“待统计”。优先计算版本核心及全部游戏目录，内容包完整声明随后读取。至少 16 个内容包时用最多 4 个线程读取声明，结果队列限 16 个条目；SQLite 写入仍在扫描线程串行进行。取消后接收但丢弃在途结果，确保发送线程退出且不再提交新条目。

`walk.rs` 流式枚举目录，Windows 文件大小直接使用 `DirEntry` 枚举元数据。当前祖先链通过目录只读枚举/属性句柄保护：`FILE_LIST_DIRECTORY | FILE_READ_ATTRIBUTES`，`BACKUP_SEMANTICS | OPEN_REPARSE_POINT`，拒绝 DELETE 共享；退出该目录或取消时释放句柄，拒绝重解析点。文件内容不打开。文件操作继续使用原严格路径与快照检查。

空间分析先枚举两层目录，至少 8 个独立子树时使用最多 4 个线程。子树内完整统计，合并只累加外部祖先，不重复累加内部文件。绘图节点总预算 100000，省略节点的字节仍在总量中。线程输出已读取文件数，UI 按请求代次更新分析进度；任务被拒绝时明确撤销“正在分析”的错误提示。

`LaunchMapping` 新增可缺省的 `script`（path / working_dir），旧配置自动得到 None，SQLite 格式仍是 v2。执行前校验映射、版本、真实根目录、实际游戏目录及脚本路径。用户指定的 BAT / CMD 使用 `ShellExecuteExW` 文件入口执行，不拼接 cmd 命令、不解析脚本内容。它与 OpenLauncher 分属两个按钮，不冒充原生 LaunchInstance 或游戏进程确认。

## 文件操作

Policy 从已添加根目录、发现的实际 Instance、应用数据和启动器路径建立保护集合。叶条目须位于已注册游戏目录的正确类别容器，数据包须位于该目录 saves 中某存档的 datapacks；独立版本整目录回收另验目录与已确认 gameDir 相等。执行时重新验证当前来源和目标，根/versions/共享及自定义游戏目录、内容容器、主目录、缓存和启动器文件禁止处理。包含任意链接的树中止。

预览后台生成最多 100000 个树节点及每文件完整 BLAKE3，明确路径、数量和大小。UI 参数签名包括选择 ID、动作、名称、源备份、目标、冲突和版本范围；输入变化使预览无效，确认入口再比较签名。执行先检查 session.lock，再逐项核对快照、复制到目标旁 .minecraft-explorer-<计划ID>-<项序号>.partial、校验副本及原件，使用 MoveFileExW 不覆盖提交。复制/备份/恢复的已提交结果保留；移动在目标提交后另记录原件回收步骤，失败时保留两份。每项保存结果后再开始下一项，取消不会回滚已完成项。正常失败只清理本任务创建且仍无链接的临时目录。

Windows 回收单独初始化 STA COM，设置 FOFX_RECYCLEONDELETE 和 FOFX_EARLYFAILURE，进度 sink 拒绝不含 recycle 标记的 PreDeleteItem；不退回永久删除。支持范围限定为本机固定磁盘。真实存档锁检查与 Windows Shell 行为分别验收；委托回收前释放程序自己的共享锁，游戏自身的 Windows 独占锁仍造成失败。备份为目录副本和版本 1 清单，运行锁不复制；恢复从备份实际内容重新计算哈希，拒绝损坏、非叶类型及不安全名称，不信任清单的原源路径。

操作记录使用同数据目录 operations 下的 JSON，写入独立临时记录、sync_all 后原子替换。源/目标和阶段结果持久化，旁置临时路径可从计划 ID 推导，重启显示未完成记录而不自动清理或重放。文件操作和扫描共用后台任务门闩，监控事件延后；完成后先迁移注释，再释放门闩并主动增量刷新，即使监控关闭也同步索引。重命名/移动会迁移世界及其数据包的注释，合并目标历史标签/收藏/最近时间；跨实例移动清除旧手动条目启动映射，继承目标实例默认。

重复检测仅在用户请求时执行，对索引中的四种内容文件先按当前文件长度分组，再串行读取完整文件计算 BLAKE3。不对目录或世界哈希，不因同名宣称重复；同一规范化物理路径去重。每次读取检查取消及路径重解析点，读取前后核对大小、mtime 与完整读取字节数，变化或不可读文件报告并跳过。相同哈希作为候选显示，不实施删除或估算已释放空间。

## 启动映射

映射同时保存 subject_id、launcher_id、root、game_dir、具体 version_id、version_path、来源。建立映射检查物理目录、根目录一致、实际独立游戏目录一致。共享目录必须由用户明确选择版本。保存关联时同时记录 subject 与实际 Instance 的默认启动器，同实例内容继承该选择；这些设置可覆盖全局默认。多个安装以独立安装 ID 保存映射，PCL CE 是独立种类，旧 PCL2/HMCL 配置保持兼容。

能力定义为 OpenLauncher / SelectInstance / LaunchInstance / TrackGameProcess。PCL2、HMCL、PCL CE 目前均只公布 OpenLauncher。PCL2/PCL CE 仅接受 EXE；HMCL 可用 EXE 或 JAR，EXE 无额外参数，HMCL JAR 传独立参数 `-jar`、JAR 路径；`Command` 设置明确 working_dir，不通过 cmd 拼接。退出状态仅描述启动器进程，不推断 Minecraft 已运行。失败时用户可手动换同根目录的其他安装，不自动运行另一安装。没有界面自动点击、修改启动器配置或读取认证信息。直接启动仍需按真实安装版本验证公开接口，研究与验收边界见 [LAUNCHER_RESEARCH.md](LAUNCHER_RESEARCH.md)。
