# 分阶段开发记录

## 1.0.0 — Fimel 单文件发行

将程序、Windows 文件版本及关于页同步为 1.0.0。保留此前已验收的扫描、空间分析、文件管理、双语和主题功能，移除正式界面的阶段编号。项目 MIT 与 345 个锁定依赖包的许可、归属原文以确定性 gzip 嵌入 EXE，关于页可主动导出到本程序数据目录查看；导出拒绝覆盖不同内容。

在 Fimel 网站现有 JSON＋Markdown 目录中注册 `minecraft-explorer` 工具作品，提供中英日概述、使用步骤、更新日志与版本说明，链接实际 GitHub 仓库。网站提供单个 `MinecraftExplorer-1.0-win-x64.exe`；截图来自生成的演示数据，未公开用户真实游戏内容或配置。

## 0.4.2 — 设置切换、应用图标与新增目录自动分析

修复 Slint ComboBox 的 selected 回调返回文字却被当作整数比较的问题。语言和主题改用控件实际 current-index，立刻更新界面；保存请求带代次，旧回执不会覆盖快速切换的新选择。

设计原创草地方块与放大镜图标，提供 SVG、PNG 和七尺寸 ICO；Windows 资源编译把图标及包版本嵌入主 EXE，Slint 窗口使用内置 PNG，不要求用户在 EXE 旁放置图标文件。

设置添加目录后选中这个目录并进入空间分析，索引刷新完成后在同一后台任务中继续分析；取消扫描会跳过分析。修复程序自动选择范围的延迟回调作废请求，以及发现实例后重复范围清空已完成小目录快照的问题。范围按去重后的物理路径集合比较。

原生验收改为真正点击下拉框和发送上下键，覆盖快速往返切换、重启保存、自动分析新增目录、取消以及首次添加小目录。目录选择器的测试结果限定为带标记的临时夹具；后续校验、存储和分析使用正式代码。具体记录见 [TESTING.md](TESTING.md)。

## 0.4.1 — 扫描性能与启动使用流程

针对实际使用反馈优化：一次扫描内复用目录子树大小，版本核心与独立游戏目录优先统计，目录监控自动补齐受影响实例总量。未知大小显示“待统计”，元信息阶段保留旧大小，取消不再留下虚假的“计算中”。

空间分析使用流式枚举和最多 4 个子树线程，复用 Windows 枚举元数据；绘图节点省略不再截断大小统计。顶部显示文件数和耗时；已有任务阻止分析时显示原因，清除假分析状态。祖先目录句柄拒绝路径改名替换，仍跳过重解析点。

详情新增“启动关联脚本”，设置关联支持目标版本专用 BAT / CMD 和工作目录。此入口执行用户选定的导出脚本，原生启动器适配仍为 OpenOnly；不读取脚本登录内容，也不假报游戏已经运行。旧映射默认无脚本，改变目标版本时清空待绑定脚本。

README 增加首次添加目录、筛选存档、启动器关联、准备与执行脚本、空间分析、备份和缓存位置的说明。实际目录性能、原生界面和打包结果见 [TESTING.md](TESTING.md)。下文保留各阶段历史记录。

## 阶段 2 — 0.2.0 全局内容管理

实现资源包、模组、光影包与世界数据包的真实目录发现、全局索引、按实例筛选和统一搜索/排序。`pack.mcmeta` 支持有界文本组件及新旧格式；模组元信息支持 Fabric、Forge、NeoForge 和旧 `mcmod.info`，只展示文件内声明，保留多模组记录及构建占位符提示。ZIP/JAR 只读指定元信息与小 PNG，不解压到游戏目录；解压预算、中央目录大小与条目数均有上限，损坏或不支持的内容仍可查真实路径。

收藏、标签与最近打开使用独立 SQLite 注释表，扫描、路径暂时消失和重新添加不会覆盖注释。查看详情、成功定位或创建所选启动器进程会记录最近打开，全部记录只写本程序数据库。v1 配置与索引事务迁移到 v2，未知更高 schema 不覆盖。

notify 原生监控对文件事件防抖，普通变化只刷新新增/受影响的叶条目，实例总大小显示待刷新，F5 完整重算。版本 JSON、官方 `launcher_profiles.json`、事件丢失或订阅恢复触发完整刷新；支持关闭监控、离线重连与根目录删除重建后的重新订阅。

重复检测只在主动请求时执行，按实际文件长度筛选后计算完整 BLAKE3；并发度 1，逐次读取可取消，并核对文件读取前后的大小/修改时间。只列出四种内容文件的重复候选，不检测重复世界，不提供删除。

列表行图标按可见行请求，由专用线程读小 PNG 并解码；使用容量 64 的请求通道与 256 个结果的缓存，按修改时间/大小/预览时间使缓存失效，缺失图标显示占位图。世界图标、包图标和模组声明图标使用同一读取限制，保留 Slint ListView 虚拟化。

新增独立 PCL CE 安装种类与 Adapter，保留旧 PCL2/HMCL 配置值。每个安装有独立路径、工作目录、根目录与映射，同实例内容继承实例默认启动器。已核查 PCL2/HMCL/PCL CE 公开入口和本机 PCL CE 对应源码提交，结论与实测边界记录在 [LAUNCHER_RESEARCH.md](LAUNCHER_RESEARCH.md)。三个适配器均保留 `OpenOnly` 与目标实例提示：真实指定实例启动仍未验证，直接启动入口继续禁用。失败允许手动换同根目录的其他安装，不会自动启动意外安装。

新增针对内容格式、归档边界、旧索引迁移、注释持久、只读哈希、原生通知与 PCL CE 多安装的回归测试。实际构建结果、测试数量、真实目录扫描和界面验收记录由 [TESTING.md](TESTING.md) 汇总；文档不把模拟启动器进程测试当作真实 Minecraft 启动成功。

## 阶段 3 — 0.3.0 安全文件操作

加入确认预览、重命名、分块复制、校验后移动、目录备份与恢复、最多 256 项多选及逐项批量提交。预览读取实际树、文件数、大小和完整 BLAKE3；执行前重验源树。用户修改参数或选择项会使预览失效，执行入口额外核对参数签名。目标重名默认停止，可显式选择序号，不覆盖现有数据。复制先创建旁置临时副本，完成源/目标校验后通过 Windows 不覆盖重命名提交，正常失败/取消清理未提交临时数据。

Windows 回收通过 IFileOperation 和 recycle-only 进度回调实现，拒绝永久删除标记；仅开放本机固定磁盘。移动在目标校验提交后才将原件回收，失败/取消保留已提交目标和原件并明确报告。版本核心回收只选择匹配目录名或已唯一识别的版本 JSON 及同名 JAR，其他配置/归档保留；整个独立实例目录是单独的确认范围，未确认独立实例时拒绝。根目录、versions、共享目录、容器、主目录、缓存和启动器文件均由核心路径策略保护。

存档 session.lock 检查文件共享及字节范围锁，活动世界中止；本程序不是 Minecraft 热备份工具。Windows Shell 自己需要访问 session.lock，因此仅在委托单项回收前释放本程序锁，实际游戏持有的 Windows 锁仍使 Shell 拒绝操作。备份不复制运行锁，包含内容和完整哈希清单；恢复验证清单后复制到正确类别目录。

操作记录在应用数据目录持久化，先写计划，移动处理原件前记录目标已提交，再记录逐项结果。崩溃后的旁置临时目录路径可从计划 ID 确定，「清理与备份」展示记录并提示人工核对，不自动删除或重放任务。重命名/移动同步注释及世界内数据包注释，目标历史注释合并；成功重命名保留手动条目映射，跨实例移动清除旧条目映射并继承目标实例设置。关闭监控时，文件操作仍会显式刷新相关索引。

同时修正数据包发现：目录/ZIP 根级必须有 pack.mcmeta 文件和 data/ 目录，支持 ZIP 隐式目录；普通 .git/tools、不完整/嵌套包排除。完整发现结束即清除已证实不符合结构的旧缓存，不必等待大世界的大小统计；离线/无法读取的缓存保留，收藏标签不丢失。已存在路径失去有效结构时，相关增量刷新也可移除旧误识别记录。具体测试与验收结果见 TESTING.md；真实游戏目录只允许只读验收。

## 阶段 4 — 0.4.0 可视化与打磨

实现后台只读空间分析、六类占用图、清理建议、按来源或实例选择范围、面积守恒的二分树图布局、目录钻取和返回、悬停路径与归属、右键定位及内容列表联动。规范路径去重使共享目录和重叠来源只统计一次；最多保留 100000 个节点和 100000 个待处理路径，每层最多绘制 256 项，微小条目合并。遇到链接、权限、取消或队列预算时显示大小下限。鼠标交互不访问磁盘，重新分析显式更新快照。

加入持久化中英双语与深浅主题。内置词典区分完整消息模板与动态字段，避免改动用户名称或路径；模板在后台预热。主题同时覆盖自绘组件和原生样式控件，设置页可滚动，列表保持虚拟化。补全内容右键动作与安全快捷键，输入框保留编辑行为，删除和重命名快捷键只进入确认流程。

修正本机 PCL CE 无法打开：真实 EXE 的 Windows 兼容性设置包含 RUNASADMIN，CreateProcess 返回 740。现在仅在该错误下对无参数 EXE 调用 ShellExecuteExW，由系统处理 UAC，并保留可查询、自动释放的进程句柄。用户取消授权有明确提示，仍不传猜测的实例启动参数，不修改启动器或兼容性设置。
